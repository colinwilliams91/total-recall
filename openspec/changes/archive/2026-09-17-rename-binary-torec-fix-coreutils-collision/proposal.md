# Proposal: rename-binary-torec-fix-coreutils-collision

## Why

The installed executable is named `tr`, which shadows GNU coreutils `/usr/bin/tr` on Linux whenever its directory precedes `/usr/bin` in PATH. A real-world incident on Omarchy Linux (documented in `docs/handoff/Upstream-Bug-Fix-Handoff_ Linux-tr-Command-Name-Collision.md`) showed the shadow breaking unrelated desktop functionality (Hyprland launcher keybinds stopped launching the terminal and Neovim because their launchers invoked `tr` through PATH). The name collision is accidental, unsafe, and must be eliminated at the source rather than worked around via PATH ordering.

## What Changes

- **BREAKING**: Rename the installed executable from `tr` to **`torec`**.
- Move the source directory `cmd/tr/` → `cmd/torec/` (required: `go install` names the binary after the package directory).
- Update build/install config: `Makefile` (`BINARY_NAME`, build/install targets), `.goreleaser.yaml` (`main`, `binary: torec`), `scripts/rebuild.ps1`.
- Update the cobra root command `Use: "tr"` → `Use: "torec"` and all user-visible invocation strings in Go source (`tr init`, `tr repo`, `tr serve`, `tr ask`, `tr asset`, `tr config`) across `cmd/torec/`, `internal/config`, `internal/hooks/scripts.go`, `internal/engine`, `internal/ai`, `internal/presentation`, `assets/`.
- Update hook script templates (`internal/hooks/scripts.go` consts and the documentation copies in `hooks/*.sh` / `hooks/*.bat`). The `# total-recall managed` sentinel and `[total-recall]` advisory prefix are **kept** — they are product labels, not typed commands, and keeping them preserves reinstall detection.
- Change PATH detection behavior: `pathdetect.go` looks up `torec` (not `tr`), and additionally warns when a stale legacy `tr` binary from this project still shadows coreutils.
- Update docs (README, CONTRIBUTING, INSTALL_LAYERS, E2E, CONFIG, AGENTS.md, FEATURES, ROADMAP, diagrams) and e2e scripts; update AGENTS.md build commands.
- Add CI/test guards: a test asserting the built binary is not named `tr`, and a Linux collision-regression test proving `tr '[:lower:]' '[:upper:]'` still resolves to coreutils when our bin dir is first on PATH.
- Add a migration note: existing users must re-run `torec repo` after upgrading so installed hooks pick up the new binary name; no backward-compat `tr` alias ships (re-shadows coreutils; precedent: the 2026-07-24 rename shipped none).

**Non-changes (deliberate):**
- Data-layer names are untouched: `~/.tr/`, `.tr.yaml`, `$TR_HOME`, and the `trDir`/`TR_HOME` APIs keep their names. They are data-state identifiers, not the executable; renaming them breaks every existing user's config with no safety gain.
- Go module path `github.com/colinwilliams91/total-recall` is unchanged; internal import paths are unchanged.
- Daemon URL (`localhost:7331`), MCP mount, hook sentinel, `[total-recall]` prefix unchanged.
- Archived openspec changes (including `2026-07-24-rename-binary-to-tr`) remain frozen as history.
- No `cmd/tr/` directory left behind as a stub.

## Capabilities

### New Capabilities

- `executable-naming`: the contract that the project MUST NOT install an executable that collides with names owned by standard Unix utilities (specifically coreutils `tr`); includes CI guard requirements.

### Modified Capabilities

- `path-detection-warning`: detection switches from `exec.LookPath("tr")` to `exec.LookPath("torec")` on Unix (and `Get-Command torec` on Windows); warning wording updated to the new command name; new requirement to detect and warn about a stale legacy `tr` binary from this project shadowing coreutils.
- `init-ai-setup`: the PATH-detection requirement text pins the renamed helper (`checkTorecOnPath`) and the `torec` lookup literals.
- `post-commit-hook`: generated post-commit script comment `# Generated by 'tr repo'` → `# Generated by 'torec repo'`; requirement text updated from `tr ask` to `torec ask` (the baked-absolute-path mechanism itself is unchanged and already PATH-collision-safe).
- `tr-ask` → renamed capability `torec-ask`: all requirement text `tr ask` → `torec ask`; behavior otherwise unchanged.
- `tr-repo-command` → renamed capability `torec-repo-command`: all requirement text `tr repo` → `torec repo`; behavior (worktree-aware hooks-dir resolution, config write, install order) unchanged.
- `cli-asset-commands`: requirement text references `tr asset show/reset/sync`, `tr serve`, `tr config show` → `torec` equivalents; behavior unchanged.

## Impact

- **Code moved**: every Go file under `cmd/tr/` moves to `cmd/torec/` via `git mv`; package/imports unchanged.
- **Code edited**: `Makefile`, `.goreleaser.yaml`, `scripts/rebuild.ps1`, cobra wiring in `cmd/torec/main.go`, string sites in `cmd/torec/{main,ask,asset,pathdetect}.go`, `internal/config/{loader,show}.go`, `internal/hooks/scripts.go`, `internal/engine/{server,mcp}.go`, `internal/ai/provider.go`, `internal/presentation/terminal/adapter.go`, `assets/assets.go`, hook doc copies in `hooks/`.
- **Tests updated**: `cmd/tr/*_test.go` literals (hook-script assertions, `Use: "tr"` in `asset_test.go`, evil-path literals), `assets/assets_test.go`; the cobra `Use` rename may affect golden files (verified: current goldens contain no binary-name text); new tests per the CI guards above; e2e scripts (`scripts/e2e/common.ps1`, `manual-init.ps1`, README) updated, and the manual e2e asserts updated.
- **Installed hooks on users' disks**: managed-hook bodies contain `tr serve`/`tr init` strings; after upgrading users must re-run the (renamed) repo command — the sentinel survives so reinstall overwrites cleanly. Post-commit hooks keep working via the baked absolute path until the binary path changes, then re-running the repo command refreshes it.
- **CI**: `ci.yml` gains the no-`tr`-name guard; release artifacts change name to `torec*` via goreleaser.
- **Dependencies**: none added/removed; `go.mod` unchanged.
